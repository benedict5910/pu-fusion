## Protocol (unchanged from the established one)

* **P1, bearing-disjoint:** same seeded design (`splits.p1_folds`, seed 0, 5 repeats × 3 folds). Test pool =
  6 healthy + 5 real OR + 6 real IR; every fold tests 5–6 unseen bearings (≈2 per class) and trains on the
  other 22–23. Artificial bearings are training-only. **All 15 designed folds are valid** (starter: 11).
  17 distinct test bearings; each appears once per repeat.
* Training rows: clean + augmented windows of training bearings only. Test rows: clean + every corruption
  tag of held-out bearings only.
* OB1 (`run_experiments.py`): 9 models, logistic-regression experts, all repetitions of held-out bearings.
  Evaluated (pooled over 15 folds): 54,315 clean + 258,400 corrupted windows per model.
* OB2 (`eval_quality_v2.py` → `ob_final_eval.py`): v2 detector configuration chosen per fold by inner
  leave-one-training-bearing-out on training bearings and seen families only (noise, dropout, intermittent,
  gain); clipping, spikes, stuck withheld. Evaluation on repetitions ≥ 2 (repetition 1 = unlabelled
  commissioning baseline) for every model: 297,070 windows per model (51,590 clean, 245,480 corrupted).
* Metrics / statistics: as `summarize.py` and `ob_final_report.py` (definitions fixed before results; abstain
  counts as wrong; paired Wilcoxon, Holm-corrected, run-level n = 15 and bearing-level n = 17).
* Also run: P2 (artificial → real, 2 folds, now possible), P3 condition hold-out (diagnostic, 60 runs),
  leaky reference split (reference only, never reported as performance).

**Code change:** `scripts/ob_final_eval.py` gained an optional `--folds` filter (3 lines; default = all
folds). Check: on the starter data, fold P1_r0_f0 reproduces the frozen `results/ob_final` predictions,
abstentions and probabilities exactly. No model, feature, metric or threshold was changed.

**Execution check** (`check_fold0/`): fold P1_r0_f0 ran end to end before the full launch.

## Leakage audit (`leakage_audit.json`)

All 8 checks PASS on the full file: bearing-disjoint folds (15/15, no artificial bearing in test); no

### Gating behaviour by scenario (`ob_final/gating_by_scenario.txt`)

* **Current faults (any family):** v2 flags current in 100 % of windows → gated_v2 uses vibration only
  (0.612, ≈ vib_only 0.629). This **protects** against current faults that hurt the always-on fusions:
  current clipping 0.05 drops early_fusion to 0.374 and gated_both to 0.61→0.53 (clipping 0.2), current
  spikes drop gated_both to 0.51–0.54. Cost: the 7.3 % of windows where vibration is also false-flagged
  are abstained.
* **Vibration dead (stuck, dropout):** vibration flagged 100 % → current-only diagnosis 0.394; vib_only
  0.240, early / gated_both 0.40. Gating helps vs vib_only, equals the learned gate.
* **Vibration mildly degraded (noise ≥ −5 dB, gain, spikes 1000, clipping, intermittent):** vibration
  flagged 96–100 % → gated_v2 falls to 0.39–0.43, while vib_only stays 0.60–0.65 (noise 0 dB: 0.652).
  This is the main failure: the detector is right that the sensor is corrupted, but the corrupted vibration
  is still far more informative than the clean current expert.
* **Both sensors noisy (0 dB):** both flagged → 100 % abstention (F1 0.00) where the other fusions keep
  0.63. At 10 dB, 38 % abstention, F1 0.445.
* The original `gated_both` hard mask never abstained (0 % in every scenario).

## Per-class and bearing-level results (clean, pooled)

* Outer race is the hardest class for every model (recall 0.42–0.44, F1 0.46–0.48); inner race recall
  0.75–0.82; healthy recall 0.65–0.68.
* **K002 is misdiagnosed as damaged in ≈100 % of windows by every model** and K005 in 55–83 %; together
  they drive most of the healthy false-alarm rate. KA22 (0.19–0.43) and KA30 (0.29–0.37) are the weakest
  damaged bearings. K001, K003, K006, KI04, KI18 are ≈ 1.0.

## Summary against the objectives

* **OB1:** bearing pipeline evaluated on the full available Paderborn set (28/32 bearings, all 15 P1 folds,
  plus P2 and P3), leakage-audited. Best clean macro-F1 ≈ 0.62 (late_average, vib_only); the fusion
  models are **not** significantly better than vibration alone. Gearbox (MCC5-THU) extension is still
  blocked by data and is not part of this run.
* **OB2:** the corrected detector (v2) holds up on the full set (large detection gains, 7 % clean false
  flags on vibration). The fusion hypothesis is **not supported**: gated_v2 equals the baselines on clean
  data, protects against current-sensor faults, but is significantly worse under seen vibration
  corruptions because it discards still-useful noisy vibration and abstains on dual noise. Same conclusion
  as on the starter subset, now with 15 runs and 17 test bearings.

## Limitations

* KA08 missing (artificial OR, training-only); KB bearings excluded by design.
* 17 test bearings, 2 per class per fold: bearing-level conclusions rest on few physical units; K002 /
  K005 behaviour dominates healthy-class results.
* Only logistic-regression experts were evaluated (the established choice); `--expert hgb` was not run.
* Corruptions are synthetic, applied to recorded signals; no real sensor faults.
* The fusion exclusion rule was fixed before evaluation. No new rule was tuned on these test results; a
  down-weighting policy chosen by inner cross-validation on training bearings remains future work.
* The OB1 FAR/miss columns (alarm replay, `summarize.py`) and the OB2 ones (window-level, `ob_final_report.py`)
  use different definitions; compare within a table only.
